## 1. 要交付什么

- **P1 · 网页上下文复习**：阅读网页时，VOKA 标出本页哪些词在 Anki 里**今日到期**；用户可以就在页面里复习这些词，评分（Again / Hard / Good / Easy）直接提交给 Anki，和在 Anki 里复习完全等价。不是今日到期的词也能在页面里练习，但**不提交给 Anki**。
- **P2 · 更多阅读介质**：在 YouTube 字幕、EPUB 电子书和文字型 PDF 里提供和网页相同的标注、查词、保存例句和上下文复习。

P2 完成后才上架 Chrome Web Store（#66 暂缓）。

## 2. 不在本轮范围内

- 德语、西语、日语（PRD FR-13、T-19），见 #70。
- P3：云翻译、云语音、本地 CLI、同步说明。
- 复习非 VOKA 笔记类型的卡片（用户自己的牌组、自定义模板、带媒体的卡）。
- VOKA 自己的复习进度或 SRS；VOKA 评分以外的任何调度修改（重置、改到期日、移牌组）。
- 扫描件 PDF 的 OCR；带 DRM 的电子书；Netflix 等其他视频网站。
- 撤销已提交的评分（用户到 Anki 里撤销）。

## 4. 今日到期：查询与判定

依据 #71 实测（Anki 26.09.3，SM-2）：

- **候选**：`cards.search`，查询 `note:"VOKA Vocabulary · English" is:due`。用笔记类型过滤，不用牌组，这样用户把卡移到别的牌组也不会漏。
- **判定**：只有 `scheduling.getDue` 返回 `dueNow: true` 的卡才算**今日到期**。`available: true` 不算；New 卡没有到期义务（`dueNow` 为 false），也不受每日新卡上限约束，所以一律不算今日到期。
- **与页面求交集**：拿本页出现的词条 Key 对应的卡片，和候选求交集。
- **刷新时机**：页面首次处理完；每次评分提交成功后；抽屉展开时距上次查询超过 5 分钟；用户点「刷新」。学习中的卡可能在几分钟后才到期，不做后台轮询。
- **挂起 / 埋起**：不算今日到期（`getDue` 返回 false，`answer` 也会拒绝）。
- 查询要批量完成，不能每个词发一次请求；一页里的到期判定控制在少数几次请求内。

## 5. 页面上的「今日到期」标注

- **高亮**：在 P0 第 10 节的规则之上加一层：今日到期的词在原有颜色上**加实线下划线**。成熟卡（间隔 ≥ 21 天，原本不高亮）到期时只显示下划线。
- **例外**：`ManualStatus = known` 的词页面上仍不高亮（也不显示下划线），但**计入**今日到期数和复习列表（#69 决定 3）。
- **一行提示与完整卡片**：今日到期的词显示「今日到期」标记。
- **底部抽屉**：摘要行「本页 N 个目标词 · M 张今日到期」（填入 P0 预留的 `due-summary` 位置），M > 0 时可点，点开进入复习。词汇列表加第五个筛选「今日到期」。
- M = 0 时明确显示「本页没有今日到期的词」，不凑题目。

## 6. 复习流程（今日到期的词）

入口：抽屉摘要里的「M 张今日到期」，或词汇列表「今日到期」筛选下的「开始复习」。顺序按词在页面中第一次出现的位置。

1. **正面**：`cards.render` 返回的 `questionHtml`，加上本页里含这个词的那句话（复用 P0 第 12.3 节的分句规则，加粗用户遇到的词形）。VOKA 词卡的正面是词条本身，本页例句不会泄露释义；如果例句里恰好含有释义语言的文字（比如中文网页），把这句话移到背面显示。
2. **显示答案**：用户点「显示答案」后显示 `answerHtml`，同时调用 `scheduling.predict` 拿到评分选项、间隔和 `stateToken`。
3. **评分按钮**：按 `predict.answers` 返回的选项显示，按钮上写 `label`（间隔为 null 时只写评分名）。不在本地计算间隔，不假定永远四个按钮。
4. **提交前确认**：再调一次 `scheduling.getDue`，`dueNow` 不是 true（比如用户刚在 Anki 里复习过）就显示「已在 Anki 里完成，跳过」，进入下一张。
5. **提交**：`scheduling.answer({cardId, rating, stateToken, elapsedMs})`。`elapsedMs` 从显示正面开始计时，上限 60 秒（与 Anki 默认一致）。提交期间按钮锁定，同一张卡同一时间只有一个提交。
6. **成功**：读回 `scheduling.get`，刷新这个词的高亮和今日到期数，进入下一张。
7. **冲突**（`1008 conflict`，token 过期）：丢掉旧的预测，重新读卡片状态，按第 4 步重新判定。**不自动重发**。
8. **结果不确定**（超时、断连）：显示「正在确认是否已提交…」，用提交前保存的 `reviews.getLatestId` 与新值比较，再用 `reviews.list({cardIds, afterId})` 找这条记录，最后读 `scheduling.get`。找到就当成功；找不到就显示「无法确认是否已提交，请在 Anki 里查看」，**不重发**。
9. 全部做完显示「本页今日到期的词复习完了」，回到列表。

所有调用都经后台网关，仍遵守 P0 的「连不上 Anki 时扩展完全不运行」（ADR-0002）。

## 7. 练习（不是今日到期的词）

- 入口：完整卡片上的「练习这个词」，或词汇列表里不是今日到期的词。
- 流程：正面（同第 6 节第 1 步）→「显示答案」→「下一个」。全程标明「练习 · 不计入 Anki」。
- 不调用 `scheduling.predict` / `scheduling.answer`，不写任何调度相关数据。#71 实测 Anki 会接受 New 卡和未到期卡的评分，所以这条必须由 VOKA 自己保证。

## 8. 本页词汇列表（FR-14）

P0 抽屉已有四个筛选（目标词 / 学习中 / 词典没有 / 全部）和列表。本轮补：

- 第五个筛选「今日到期」（第 5 节）。
- 每个词显示本页出现次数；可按「首次出现位置」（默认）或「出现次数」排序。
- 评分成功或 Anki 状态变化后，列表计数和筛选自动重算。

## 9. 新增的 v1 方法

网关的 `api.describe` 检查加入：`cards.search`、`cards.getMany`、`cards.render`、`scheduling.getDue`、`scheduling.get`、`scheduling.predict`、`scheduling.answer`、`reviews.getLatestId`、`reviews.list`。

产品代码仍然**不调用**：`collection.sync`、`scheduling.answerMany`、`scheduling.setDueDate`、`scheduling.reset`、`cards.move`、`noteTypes.editStructure`、删除类方法。`scheduling.answer` 只在第 6 节的流程里调用。

## 10. 阅读器共用的前置改造（P2 前做）

P0 的取词、分句和高亮代码直接使用全局 `document`。EPUB 的章节在 iframe 里，PDF 的文字在 PDF.js 文本层里，所以先把这些函数改成接收目标 `Document`（或从 `ownerDocument` 推出），并在那个文档自己的 `CSS.highlights` 里注册高亮（#73 实测：只在父页面注册不会作用到 iframe）。查词、等级匹配、释义选择保持共用。

## 11. EPUB 阅读器

- **位置**：扩展内部页面 `reader.html`，从工具栏菜单的「打开电子书 / PDF…」进入；用 `<input type="file">` 选文件，不申请 `file://` 权限，书不上传。
- **解析与渲染**：foliate-js 的 `makeBook(File)` 解析书和 CFI；每章放进 `<iframe sandbox="allow-same-origin">`（不给 `allow-scripts`），章节内去掉事件属性、外链资源和外部 CSS，再加章节 CSP（见 #73 报告第 2 节）。书内图片、字体解析成 Blob URL。
- **安全**：书里的脚本不运行，外部资源不请求；限制压缩包大小和解压后总量（超出提示「文件太大」）。
- **阅读**：上一章 / 下一章、章内滚动；目录。分页模式不在本轮。
- **标注与查词**：与网页相同（P0 第 10–12 节、本文第 5 节），抽屉同样有词汇列表和复习。
- **例句来源**：「书名 · 章节名 · 日期」。
- **阅读位置**：按文件内容的 SHA-256 存在 `chrome.storage.local`（键 `reader-position:<sha256>`），存 CFI；重新打开同一本书时恢复。不存文件路径。

## 12. 文字型 PDF 阅读器

- 同一个 `reader.html`，用 pdfjs-dist；worker 打包在扩展里，文件以字节传入，不让 PDF.js 请求任何 URL。PDF.js 只在阅读页加载，不进内容脚本。
- 每页渲染 canvas + 文本层；标注、查词和复习作用在文本层上。文本层会把一个词或一句话拆成多个节点，取词和分句要先拼出整页文字流并保留到 DOM Range 的映射。
- **扫描件**：打开时检查前几页，没有可用文字就显示「此 PDF 没有可识别的文字层，暂不支持」；部分页没有文字时，这些页上显示同样提示。
- **例句来源**：「文件名 · 第 n 页 · 日期」。
- **阅读位置**：`{pageNumber, normalizedPageOffset}`，按 SHA-256 存，规则同第 11 节。

## 13. YouTube 字幕（待 #72 定稿）

PRD 第 11 节的目标不变：显示 VOKA 自己的字幕行（按时间同步、逐词标注、悬停查义），悬停字幕或释义层时暂停，只在「暂停是 VOKA 触发的、期间用户没有自己暂停 / 播放 / 拖动 / 换视频、鼠标已离开」时恢复，可关闭自动恢复；视频词汇四筛选（新词 / 学习中 / 词典没有 / 全部，外加今日到期）；视频上下文复习复用第 6–7 节。没有可读取的字幕时明确告知。

取字幕的方式、判断用户操作的事件、页面切换的处理和最少权限，等维护者用研究扩展在自己的 Chrome 里测完（#72）再写入本节。自动化浏览器在 YouTube 上被要求登录（`LOGIN_REQUIRED`）并被限流（HTTP 429），所以 YouTube 相关的验收也要在维护者的浏览器里人工做。

## 16. 已知风险与待验证

- **FSRS**：只实测了 SM-2；FSRS 下的按钮和间隔要人工确认（第 14 节）。
- **逾期卡**：`scheduling.setDueDate` 设负天数报内部错误，逾期卡的 `getDue` 行为没实测；按 `dueNow` 判定应当同样成立，P1 验收时用真实逾期卡确认。
- **体积**：PDF.js worker 压缩后约 470 KB，只放在阅读页；离线数据已占约 4.8 MB。
- **YouTube**：内部数据和播放器接口不是公开接口，随时可能变化；失败时要能明确降级（第 13 节）。
- **EPUB 兼容**：固定版式、竖排 / 从右到左、音视频、超大或损坏的压缩包没有覆盖。
