# 每门学习语言一个笔记类型，核心字段一次定齐，释义语言靠 CSS 切换

给已有的 Anki 笔记类型增删或重排字段，会强制用户做一次单向全量同步；改 CSS 和模板文本、或者新建一个笔记类型，都不会（实测）。所以我们决定：每门学习语言一个笔记类型（如 `VOKA Vocabulary · English`）。它们共用 15 个核心字段，依次是 `Key`、`Word`、`Variants`、`Reading`、`GlossNative`、`GlossTarget`、`Context1`/`Source1` 到 `Context3`/`Source3`、`ManualStatus`、`Audio`（预留）、`VokaMeta`。某门语言需要额外字段时，只在第一次创建它的笔记类型时追加在核心字段之后；建好以后永不增删字段。释义字段按角色命名（母语释义、单语释义），不按语言命名。两种释义都写在背面模板里，显示哪一种只由 CSS 中 `/* voka:begin */ … /* voka:end */` 标记段内的规则决定。某种释义为空时，模板输出一个缺失标记元素，并把两个缺失标记放在两个释义元素之前，这样回退只靠兄弟选择器 `~` 就能实现，不依赖 `:has()`。

## Considered Options

- **所有语言共用一个笔记类型**：释义语言是每门学习语言各自的设置，共用一个笔记类型就得在模板里加语言标记、写按语言区分的 CSS；而且以后某门语言要加特有字段时，就会让所有语言的笔记都经历一次全量同步。
- **释义字段按语言命名（GlossZh / GlossEn）**：不能推广到「英语母语者学德语」这种情况。
- **用 `:has()` 做回退**：AnkiMobile 25.09 支持，但 AnkiDroid 没测；调整元素顺序后，兄弟选择器就能覆盖两个方向，不必冒这个风险。

## Consequences

- 词条等级用标签 `voka::level::XX` 表示，所有 VOKA 笔记都打 `voka` 标签，因为用户可能在 Anki 里手动移动卡片的牌组。
- `VokaMeta` 里记录扩展生成的字段（释义、音标）在写入时的内容哈希和数据版本号。数据升级时，更新预览把笔记分成「用户没改过的」（可一键批量确认）和「用户改过的」（逐条对比，默认保留用户版本，可单条或整组改用新版）；用户确认前不写入。
- 母语和学习语言相同时，只填 `GlossTarget`，并隐藏释义语言开关；不支持中途更换母语时迁移已有笔记。
- 例句来源默认只存「站点域名 · 页面标题 · 日期」，存完整 URL 是个默认关闭的开关，因为笔记会随 Anki 同步到 AnkiWeb。
