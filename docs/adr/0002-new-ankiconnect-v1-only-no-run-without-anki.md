# 只支持新版 AnkiConnect 的 v1 接口，连不上 Anki 时扩展完全不运行

VOKA 是新项目，不背历史包袱：只支持 Anki 26.08 以上配新版 AnkiConnect（sr.ht 重写版），并且只调用它给新应用的 v1 JSON-RPC 接口（`POST /api/v1`，API Key 用 `Authorization: Bearer` 头传递），不使用 v6 兼容层。每次开始工作前，用 `api.describe` 检测对方是不是新版 AnkiConnect、支不支持需要的方法。只要连不上 AnkiConnect、版本太低或检测不出来，扩展就**完全不运行**：不高亮、不能查词、不写入 Anki，只提示用户检查 Anki 是否在运行、版本是否为 26.08 以上。

## Considered Options

- **兼容 Anki 23.10 以上、新旧两代 AnkiConnect**：能覆盖还没升级的用户（26.08 发布才两三个月），但网关要同时处理两代的不同失败语义（如批量添加笔记逐条失败 vs 整批失败），还要多维护一套旧版测试环境。拒绝的理由是：不为历史版本背负复杂度。
- **只调用 v6 兼容层**：两代共用同一种请求格式时才有意义；只支持新版以后，v1 的 `notes.validateMany`、`scheduling.predict`、`operations.get` 等方法更贴合 VOKA 的预检写入、间隔预测和结果回查需求。
- **断连时降级为只用离线词典**（PRD 原方案 FR-12）：没被采用。VOKA 的高亮依赖 Anki 状态，没有 Anki 时的半残体验不值得维护一条单独的代码路径。

## Consequences

- PRD 的 FR-12（断连降级）和 T-01（连接失败）的预期结果改为：扩展完全不运行，并显示提示。
- 读到一半时 Anki 断开：撤掉页面上已显示的高亮和弹窗，侧栏显示提示；不在后台一直重试，用户点「重试」、刷新页面或打开新页面时再检测，连上后自动恢复。
- 之前在 v6 接口上实测得到的行为（判重、批量写入、全量同步），要在实现阶段用 v1 接口重新验证。
