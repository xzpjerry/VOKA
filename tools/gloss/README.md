# Native gloss pipeline

`prompt.txt` is the shared, versioned prompt for every generation path.

## Pilot (research only)

`pilot.py` produced the 300-word model comparison in
[`docs/research/gloss-pilot/`](../../docs/research/gloss-pilot/README.md). It
samples across CEFR bands, calls Codex CLI for `gpt-6-luna`/`gpt-6.1-sol` and
OpenCode CLI for the DeepSeek column, validates mechanically, and writes the
comparison CSV. Keep the three model directories together as one research
snapshot. The pilot is deliberately limited to 300 words.

## Full corpus (`generate.py`)

`generate.py` is resumable and model-selectable. It currently holds a **partial
pack**: 342 / 745 batches, 34,199 / 74,441 lemmas, all generated by
`deepseek/deepseek-flash`. The exact state and resume command are in
[`docs/research/gloss-full/progress.json`](../../docs/research/gloss-full/progress.json).
Do not describe the committed pack as complete until `complete` is `true`.

```sh
# Coordinator-authorized continuation: preserve DeepSeek cache, use Luna max.
python3 tools/gloss/generate.py --model gpt-6-luna --effort max --timeout 1800

# Current OpenCode route (DeepSeek V4.1 Flash 1017).
python3 tools/gloss/generate.py --model deepseek/deepseek-flash --workers 4 --batch-size 100
```

* Corpus: all 74,441 single-word lemmas in the committed `public/data/oewn.json`.
  POS groups merge OEWN sense-number suffixes (`n-1` + `n-2` → `n`). The input
  records (`lemma`, `level`, `pos`, `oewn`) and the prompt are the same shape and
  rules as the pilot.
* `--model` selects the CLI route: provider-prefixed names (`deepseek/…`,
  `opencode/…`) use `opencode run --format json -m <model>`; other names (for
  example `gpt-6-luna`, `gpt-6.1-sol`) use the pilot's `codex exec -m <model>`
  command with the same JSON Schema, the selected `--effort` (default `low`), ephemeral read-only
  session and empty temporary directory. Neither route reads, prints or invents
  an API key; the CLIs use their configured credentials.
* Every batch request is cached under `.cache/gloss/batches/` by its content
  SHA-256. The request hash deliberately excludes the model: a batch produced
  by an earlier model is reused when a later run selects another model, so
  resuming only generates missing batches. Every cache record stores the
  `model`, `runner` and Codex `effort` that produced it, and the pack metadata lists all
  models used and their effort configurations, so a mixed-model pack is explicit. The cache is gitignored and
  never committed.
* Four concurrent calls by default. Transport errors, including HTTP 429/5xx and
  empty answers, retry with exponential backoff and jitter (six attempts by
  default). A batch result that is parseable but fails the mechanical format
  validator is cached, then its words are retried in up to two fresh rounds.
* Writes `public/data/gloss-zh.json` as a separate, independently versioned
  pack with the OEWN source URL, CC BY 4.0 attribution and Princeton notice
  pointer, all model ids and effort configurations, prompt SHA-256, generated date, data version, entry
  count, `complete` flag, coverage and the exact missing-lemma list. It also
  updates `public/data/sizes.json` and `public/data/attributions.json` so the
  Options About section shows the new source.
* Writes `docs/research/gloss-full/progress.json`, `stats.json` and a
  30-row-per-level `spot-check.csv` for human review.

Useful partial commands:

```sh
# Rebuild the pack, progress file and metadata from the existing cache without
# any new model calls.
python3 tools/gloss/generate.py --assemble-only

# Generate only the first 5 batches (never writes the production pack).
python3 tools/gloss/generate.py --limit-batches 5
```

`--assemble-only` is the inspection path; a normal run assembles at the end and
uses the same cache. Batch membership is intentionally stable and deterministic, so
the resume command is exactly the command above with the chosen model.
